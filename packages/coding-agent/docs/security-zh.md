# 安全

Pi 是一个本地编程智能体。它以启动进程的用户账号权限运行，并将该用户可写的文件视为处于同一个本地信任边界内。

## 项目信任

项目信任机制用于控制 Pi 是否加载项目本地的设置、资源、包和扩展。它不是沙箱，也不会限制模型在你进入某个目录开始工作后可以要求工具执行哪些操作。

从当前工作目录开始查找时，只要发现以下任一内容，Pi 就会认为该项目包含必须获得信任后才能加载的资源：

- `.pi/settings.json`
- `.pi/extensions`、`.pi/skills`、`.pi/prompts` 或 `.pi/themes`
- `.pi/SYSTEM.md` 或 `.pi/APPEND_SYSTEM.md`
- 当前目录或某个祖先目录中的项目级 `.agents/skills`

仅存在一个空的 `.pi` 目录，不会被视为包含需要信任的项目资源。

在包含受保护资源的项目中启动交互式会话时，如果当前目录及其父目录都没有已保存的信任决定，Pi 会采用全局设置中的 `defaultProjectTrust`。其默认值为 `"ask"`，即在界面可用时询问是否信任该项目。保存的决定会按规范化后的目录写入 `~/.pi/agent/trust.json`；在应用全局默认值之前，Pi 会优先采用当前路径或父路径上距离最近的已保存决定。

信任项目后，Pi 可以加载以下需要信任的项目资源：

- `.pi/settings.json`
- `.pi` 下的扩展、技能、提示词模板、主题和系统提示词文件等资源
- 项目设置中已配置但尚未安装的包
- 项目本地扩展，以及由项目包管理的扩展

拒绝信任会跳过受保护资源。除非禁用了上下文加载，否则无论项目是否受信任，Pi 都会加载 `AGENTS.md` 和 `CLAUDE.md` 上下文文件。在信任状态确定之前，Pi 只加载上下文文件、用户级/全局扩展以及通过 CLI `-e` 指定的扩展。用户级、全局和 CLI 扩展都可以处理 `project_trust` 事件；第一个返回明确“是/否”决定的扩展将负责此次决定。

非交互模式（`-p`、`--mode json` 和 `--mode rpc`）不会显示信任提示。如果没有适用的已保存决定，`defaultProjectTrust: "ask"` 和 `"never"` 都会忽略这些资源，而 `"always"` 会信任它们。可以使用 `--approve`/`-a` 或 `--no-approve`/`-na`，仅针对本次运行覆盖项目信任设置。

## 不内置沙箱

Pi 不包含内置沙箱。内置工具可以使用 Pi 进程的权限读取、写入和编辑文件，也可以运行 Shell 命令。扩展是以同等权限运行的 TypeScript 模块。包安装程序、Shell 命令、语言服务器、测试命令和其他开发工具的行为都与普通本地进程相同。

这是有意为之。Pi 的设计目标是在本地源码树上操作、调用项目工具链，并与用户现有的开发环境集成。如果只在进程内部实现一个不完整的沙箱，人们很容易误以为它构成了安全边界，实际上它仍然依赖宿主机的 Shell、文件系统、包管理器、凭据和扩展代码。真正的隔离必须由操作系统或虚拟化/容器边界提供。

项目信任只是一道输入加载保护。它可以防止仓库在获得你的批准之前静默修改 Pi 的设置或扩展，但无法让不受信任的代码、提示词或模型输出变得安全。来自仓库文件、注释、文档、上下文文件或构建输出的提示词注入，是本地智能体固有的风险，Pi 无法可靠地消除这种风险。

## 运行不受信任或无人监督的任务

对于不受信任的仓库、你不准备密切检查的生成代码，或者无人值守的自动化任务，应在隔离环境中运行 Pi。可以使用容器、虚拟机、微型虚拟机、远程沙箱或受策略控制的沙箱，并且只向其中提供任务必需的文件和凭据。

[容器化](containerization-zh.md)文档介绍了以下常见方案：

- 在容器或沙箱中运行整个 `pi` 进程
- 在宿主机上运行 Pi，同时将内置工具的执行转发到 Gondolin 微型虚拟机
- 只挂载智能体应当访问的工作区路径
- 除非容器确实需要访问宿主机的会话、设置和凭据，否则不要挂载宿主机的 `~/.pi/agent`
- 只传入最低限度的 API 密钥，或使用短期凭据
- 如果任务不需要网络，则限制网络访问
- 将结果复制回受信任的系统之前，先检查差异和输出

如果以读写方式绑定挂载宿主机工作区，容器或虚拟机内的写入仍然能够修改宿主机文件。需要更严格地防止意外写入时，应使用只读挂载，或者通过复制的方式将文件移入、移出沙箱。

## 报告安全问题

如需报告安全问题，请遵循仓库的[安全策略](https://github.com/earendil-works/pi-mono/blob/main/SECURITY.md)。请勿为涉及敏感安全信息的报告创建公开 Issue。

本地智能体的预期行为、不内置沙箱、来自不受信任内容的提示词注入，以及用户自行安装的扩展或技能的行为，通常不属于安全边界问题。只有当报告能够证明存在真正的权限边界绕过，或说明 Pi 如何授予了本地用户原本不具备的访问权限时，才属于例外。
